# 立项书 v1 · Seal（暂定名）

## 一句话
给 agent 干的活盖个章：一条命令生成**可核验的交付凭证**，对方能验，下一个 agent 能接手。

## 为什么是这个（调研结论，2026-11-15）
- GitHub `agent-skills` 话题下 4.4 万个仓库，绝大多数在**加能力**（画图、写文案、找岗位、做数据库…），MCP 榜单前 50 也全是**加工具**（浏览器、代码记忆、设计稿、搜索）。
- 记忆层（Cognee / Graphiti / Beads）、工作流（Superpowers / OpenSpec / Task Master）、安装前安全审计（skill-security-auditor）都有人做。
- **空位**：没有人做「agent 交付的验收与交接」。学术上只有 PROV-AGENT（arXiv 2508.02866）这类溯源模型，工程上没有开箱即用的东西。
- 我们的差异化来自一条朴素经验：任何要交出去的活都该带一张能对得上号的凭证，把它搬到 agent 世界——**内容哈希 + 防篡改链 + 一页给人看的凭证**。

## 三个用户痛点（来自真实使用，不是想象）
1. **对方（老板/客户）不敢信**：agent 说"做完了"，到底改了哪些文件、跑没跑测试、跑的结果是什么？现在只能翻聊天记录。
2. **换会话就失忆**：上下文一压缩、一换模型，接手的人（或 agent）要从头问一遍。
3. **改了也不知道有没有被改**：交付物在传递过程中被动过手脚、被顺手改一行，没人能证明。

## 产品形态
单文件 Node CLI（零依赖、离线），配一个 agent skill：

```
seal            # 在当前目录生成交付凭证（自动收集：改动的文件、跑过的命令、测试结果、git 状态）
seal verify     # 任何人拿到凭证都能验：文件哈希对不对、命令结果对不对得上
seal resume     # 给下一个 agent/人一份「接手简报」：做到哪、验过什么、下一步做什么
seal show       # 打开一页 HTML 凭证（可打印、可转 PNG）
```

## 凭证里必须有什么（这是我们的护城河，别家没有）
1. **改了什么**：文件清单 + 每个文件的 SHA-256 + 增删行数（不贴全文，只贴指纹）。
2. **跑过什么**：命令原文、退出码、输出摘要哈希、耗时。
3. **结论是什么**：做完/没做完/卡在哪，一句人话。
4. **防篡改**：凭证自身带链式哈希（每段带前一段的哈希），改一个字就能验出来。
5. **能验收**：`verify` 会**真的重跑**声明里的校验命令，比对输出指纹，不一致就红。

## 差异化（对外一句话）
> 别的工具帮 agent 多做一点，Seal 让 agent 做的每一点都能被验收。

## 受众（不局限老板的行业）
- 用 Claude Code / Codex / Cursor / DSH / opencode 的个人开发者（自证交付）
- 外包/自由职业者（给客户交活时附一张凭证，减少扯皮）
- 小团队 Tech Lead（验收下属的 AI 产出）
- 合规与审计场景（研发过程留痕）——老板本行，但只作为加分场景，不作为主卖点

## 今晚要交的东西（验收清单）
1. `seal` CLI 能在 Windows 直接跑（node 单文件，无 npm install）。
2. 三条命令跑通并有真实输出：seal / verify（含篡改后验不过）/ resume。
3. 一页 HTML 凭证，浏览器打开像正经文件（有标题、编号、时间、哈希、结论、可打印）。
4. README（中英）+ 3 分钟上手 + 截图。
5. 一个 demo 仓库：故意做一次"交付→篡改→验不过"，作为演示脚本。
6. 自测脚本 `npm test` 或 `node test/run.js`，全绿。
7. 我逐项跑一遍，录成文字证据。

## 不做什么（今晚）
- 不做云端、不做账号、不做数据库。
- 不做 VS Code 插件、不做 MCP server（放二期，README 里写"路线图"）。
- 不做花哨动画；凭证要像公文，不像 PPT。
